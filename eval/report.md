# 評估報告（線索偵測）

> 改版為「說清楚」後，這裡的規則不再對使用者顯示成漏洞，而是當作找卡點的**線索**。本報告只評估線索偵測；「問題草稿是否說中使用者真正的問題」需要真人測試，目前沒有評估。

> **警告：以下數字來自 `eval/gold.json` 的 40 筆合成資料（`labeled_by: "draft"`），由同一個開發流程撰寫與標註，不能當作真實準確度。** 真實準確度需以真實輸入與人工標註重新評估。
>
> 設計改為「推論成立就放行，只問結構性盲點」後，g07～g09 依新設計改標為無漏洞；g31～g40 是改版後新寫、改規則時沒有用過的「推論成立」案例。改為「說清楚」後，g07、g09 標為 `troubled: true`（原文本身就是困擾，應該問一題），不列入「完全不問」的分母。

- 資料筆數：40（應有漏洞 18、應無漏洞 22）
- 門檻 threshold：0.35；每次最多輸出 2 項

## 失敗案例

### g04

```
因為我胖，所以沒人喜歡我。
```
- 期望：CAUSAL_JUMP、OVERGENERALIZE；實際：CAUSAL_JUMP
- 骨架輸出：無可確認事實
- 提問：「沒人喜歡我」這件事，除了「我胖」，還有沒有別的原因你想過？有，或沒有？
- 問題：漏報 OVERGENERALIZE
- 全部候選：CAUSAL_JUMP:0.63

### g06

```

```
- 期望：CAUSAL_JUMP、UNDEFINED_TERM；實際：（無漏洞）

- 問題：漏報 CAUSAL_JUMP；漏報 UNDEFINED_TERM；應有漏洞卻輸出「未發現實質漏洞」；骨架未命中（期望含「昨天沒睡好」）
- 全部候選：CAUSAL_JUMP:0.33 UNDEFINED_TERM:0.3 UNDEFINED_TERM:0.15
